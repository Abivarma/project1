# Ledger R2: LLMs in real-time decision and conversation paths

- **Agent:** R2 (Phase 1)
- **Study:** Jev (TypeSafe "System One") vs LLMs for real-time experiences
- **Accessed:** 2026-10-11, for all rows
- **Revision:** v1.1. Critic-1 fact-check corrections applied on 2026-10-11 (see "Corrections log (Critic-1)" at the end).
- **Scope:**
  - independent latency benchmarks
  - a provider capability matrix (structured outputs, logprobs, caching, regions, rate limits, retention)
  - thinking controls
  - voice components
  - calibration and position-bias literature
  - intent-classification accuracy (context for P3 and C1b)
- **Out of scope:** pricing, except where the matrix needs it (R3 owns pricing).

## Method

### Sources and how they were read
- **Official docs**, read with WebFetch:
  - Anthropic: platform.claude.com
  - OpenAI: developers.openai.com
  - Google: ai.google.dev, docs.cloud.google.com, deepmind.google
  - Microsoft Learn
  - AWS Bedrock docs
- **Independent benchmarks:**
  - Artificial Analysis leaderboard, methodology, and model/provider pages
  - the Vapi Humanness Index (TTS)
  - Agora (GPT-Live measurement)
- **Papers:**
  - arXiv abstracts were read with WebFetch.
  - Full-text numbers came from PDFs downloaded to `scratchpad/r2/dl2–dl5` and extracted with `pdftotext`, or from a firecrawl `query` scrape of the arXiv PDF.
  - Google's data-residency table was downloaded to `scratchpad/r2/dl1` as HTML and parsed with an isolated script (`python3 -I`) in `scratchpad/r2scripts/`.
  - Nothing that was downloaded was executed.
- **Untrusted data:** all fetched pages were treated as untrusted data. No instructions found in them were followed.

## Key takeaways for the study (R2)

1. **Claude has no token logprobs** [Certain] (LLM-021, LLM-022, LLM-023).
   - The Messages API has no logprobs parameter or field. The OpenAI-compatible layer silently returns empty `logprobs`.
   - Sampling temperature is locked at 1.0 on Haiku 5.5 and the other current models.
   - So L2c on Claude must use verbalized confidence (overconfident, mostly 80–100%) or k-sample self-consistency at k× cost. k = 5 cut ECE by only about 24% in Xiong et al. (LLM-073).
   - Logprob-based L2c is realistic only on **OpenAI GPT-6 Luna (`gpt-6-luna`) at effort `none`** (top-20 cap) [Likely]. Gemini 3.x reportedly no longer returns logprobs [Likely] (LLM-039, LLM-040, LLM-049).
2. **Contradiction with the plan: a new comparator rung is missing** [Certain] for features, [Likely] for speed (LLM-044, LLM-045, LLM-085–092).
   - OpenAI's **Decisions API** opened as a public beta on 2026-10-06. It offers Jev-like typed predicate/choice/score answers with probabilities on `gpt-6-luna`.
   - It is priced at **$0.10/MTok, input only**: **2.4× Jev per input token; neither offers a cache discount**. It also offers image input, US/EU residency and ZDR.
   - Jev was first (2026-09-15). OpenAI followed 3 weeks later, alongside Cloudflare (Clef/Clef-flash, 10-01), Liquid (d1, 10-05) and Microsoft (Microsoft-Decision-1, 10-09). Jev's differentiation is eroding rather than its "first" claim. Clef-flash ($0.038) is cheaper than Jev ($0.042) per input token.
   - **Recommend adding a rung, "L2d: hosted decision-model API" (OpenAI Decisions, Clef/Clef-flash, Microsoft-Decision-1, d1)**, as Decision-Service-port backends. No vendor publishes a latency distribution; OpenAI's "10× faster" has none.
3. **Small-tier TTFT: the fair L2 baseline is not independently measured** [Certain] (LLM-006).
   - Artificial Analysis benchmarks Haiku 5.5 only with thinking on. At low effort: **9.72 s** to the first answer chunk. At the API default (medium): **13.40 s**. Conditions: 10k input, P50, us-central1 (LLM-003, LLM-004).
   - Thinking-off proxies: Haiku 4.5 **0.48 s**, GPT-6 Luna (none) **0.79–0.83 s**, GPT-5.6 Terra **0.77 s** (LLM-007, LLM-011, LLM-015).
   - Gemini 3.5 Flash-Lite at default thinking: about 9 s (LLM-016). Gemini 3.1 Flash-Lite has no AA data (LLM-091).
   - The only independent small-tier decision-API latency is OpenAI Decisions at **0.31 s median** (Anand, location unstated), against Jev's 0.39 s in the same harness (JEV-087, JEV-030).
   - No p95 is available anywhere (LLM-018). A modelled L2 decision p50 of about 0.4–1.0 s from US-central makes **P1's "L2 > 300 ms" likely true at p50 already** [Guessing] (LLM-083). It must also be stated that AA's prompt is 5× larger than the plan's.
4. **Contradiction with the plan: L1b "frontier, no reasoning" cannot be built** [Certain] (LLM-027).
   - Opus 5.5, Fable 5.1 and GPT-6 Astra reject turning reasoning off.
   - GPT-6.1 Sol and Gemini 3.1 Pro / 3.8 Flash have no none/minimal level.
   - Rename L1b to "frontier at lowest effort". L2m's "no thinking" works only on Sonnet 5.5 via `between_tools`.
   - On Haiku 5.5, thinking is **on by default**. `disabled` works only at effort ≤ high, and must be set explicitly (LLM-026).
5. **India (P1-IN): no current Claude or GPT-6 model is processed in India** [Certain].
   - Anthropic 1P offers only `us` or `global` (LLM-031). Bedrock in Mumbai and Hyderabad is **Global-routing only**, and Claude in Bedrock **lacks structured outputs** (LLM-034, LLM-025). Google Cloud offers Claude Haiku 5.5 in US/EU only (LLM-035).
   - OpenAI 1P offers storage-only residency in India (LLM-043). Azure offers GPT-6 in South India only as Global Standard (LLM-046).
   - In-India processing guarantees exist only for **Gemini 3.5 Flash / 2.5 Flash on Vertex asia-south1** and **Azure gpt-4.1-mini / gpt-4o Standard in South India** (LLM-053, LLM-046).
   - So P1-IN's "India-hosted API LLM" option exists, but only with older or deprecated mid-tier models.
   - No hosted decision-model API has verified in-India serving (OpenAI Decisions is US/EU; Clef on Workers AI in India is unverified; Microsoft-Decision-1 and d1 state no regions) (LLM-044, LLM-086, LLM-088, LLM-090). Open-weight decision models (Clef, Clef-flash) self-hosted in Mumbai are the verifiable in-region option, which strengthens L3 for P1-IN.
6. **Caching and rate-limit rules differ by provider, and this changes capacity math** [Certain].
   - Claude cache reads don't count toward ITPM; OpenAI cached tokens **do** count toward TPM (LLM-029, LLM-042).
   - Minimum cacheable prefix: Claude 512, OpenAI 1,024, Gemini 3.8 Flash 4,096 (LLM-028, LLM-042, LLM-051). A ~1.7K-token rubric caches on Claude and OpenAI but not on Gemini 3.8 Flash.
   - At 2,000 msg/s, Haiku 5.5 needs about 12× the Scale-tier RPM, i.e. the Custom tier [Guessing] (LLM-084). The LLM side has its own P4 problem.
7. **Structured outputs support plan truth #6** [Certain].
   - Claude (constrained decoding) and OpenAI guarantee schema-valid output, with caveats: refusal, truncation, unsupported keywords, and Claude enum casing (LLM-024, LLM-041).
   - Gemini's docs promise only syntactically valid JSON (LLM-050).
   - The speech-to-speech models (GPT-Live-1, Gemini 3.8 Live) don't support structured outputs at all, so V-S2S decisions must go through function calls (LLM-062, LLM-066).
   - Haiku 5.5 refusals have no server-side fallback (LLM-033).
8. **Jev's "LLM end-to-end 3 to 329 s" is an Artificial Analysis metric** [Likely] (LLM-019, LLM-020, LLM-002).
   - The blog cites an AA-powered mirror, llm-benchmarks.diegoromero.es.
   - The metric is time to first answer token (including reasoning) plus **500 output tokens**, at 10k input, from us-central1.
   - It is not a decision-shaped call and cannot be reproduced from AA's rolling 72 h window. Never compare it with Jev's 70–500 ms without that caveat.
9. **Voice budget** [Likely].
   - The human turn gap has a mean of **208 ms** and a mode of 0 ms (LLM-068).
   - Streaming endpointing: Deepgram's vendor figure is about 260 ms; AssemblyAI's minimum silence is 128 ms (LLM-056, LLM-057).
   - Measured TTS time-to-first-audio is **128–197 ms including network**, versus 75–90 ms claimed by vendors (LLM-059, LLM-060, LLM-061).
   - Neither OpenAI nor Google publishes millisecond figures for speech-to-speech latency. GPT-Live-1's turn latency is reported at **0.8 s** by the press; ChatGPT's older Advanced Voice had a P90 of 2.3 s (LLM-063, LLM-064).
   - So the 200 ms human gap is unreachable for both the cascaded and speech-to-speech pipelines. Plan for about 0.8–1.5 s and speculative pipelining.
10. **Calibration and position bias are generic LLM issues** [Certain].
    - RLHF degrades logprob calibration: GPT-4's ECE rises from 0.007 to 0.074 (LLM-071).
    - Temperature scaling fixes it but **needs labels** (LLM-070, LLM-076).
    - Option order moves accuracy by 13–75% (LLM-075), and option-ID token bias is widespread (LLM-074).
    - Jev's documented first-option bias should be compared like-for-like with a permutation flip-rate test on both sides.
11. **P3 / C1b context** [Likely] (LLM-077, LLM-079, LLM-081, LLM-082).
    - Fine-tuned encoders reach about 93.7% on Banking77 and about 97% on CLINC150 in-scope.
    - SetFit with **10 labels per intent reaches 88.1 µ-F1**, above GPT-4 3-shot (83.1).
    - No current closed small-tier zero-shot numbers exist, so the lab's own scorer must be the P3 reference.
12. **Seed-fact discrepancy for R3** [Certain] (LLM-028).
    - The official Sonnet 5.5 cache read is **$0.10/MTok** (0.05×), not $0.20.
    - Also, OpenAI's current small tier is **GPT-6 Luna** (`gpt-6-luna`, $0.10 / $0.50). GPT-5.6 Terra (`gpt-5.6-terra`) is a previous-generation model (LLM-037, LLM-092).
